# PC-Hydro: inputs, runs, hydrograph QC and DSS

End-to-end PC-Hydro workflow: **get basin inputs (report extract or GIS build) -> run them on the
PC-Hydro website (interactive or batch) -> save native printouts, hydrographs and .pk6 -> QC the
export and make the audited routing copy -> build RAS + HMS DSS files.**

The website is always how peaks and hydrographs are produced; there is no offline PC-Hydro engine.
Keep the `.pk6` inputs so any run can be repeated by hand if the web app changes.

## When to use
- Peaks, program printouts or 1-min hydrographs are needed for watersheds under 1 sq mi in Pima
  County RFCD jurisdiction (or a jurisdiction that accepts PC-Hydro; see add-ons).
- A prior report's basin inputs must be re-entered to rebuild its hydrographs.
- Many small watersheds on a large site, or offsite washes entering a model domain, need CPs, `.pk6`
  files and inflow hydrographs (Phase 1b).
- PC-Hydro hydrographs must go into HEC-HMS, HEC-RAS, FLO-2D or a report table.
Not for watersheds over 1 sq mi in Pima County: route those to hechms-headless.

## Inputs
- Source of basin parameters: report PDF/Excel/Word (confirm the table or appendix with the user), or
  a conditioned DEM plus land-use, soil and structure inventory for a GIS build.
- Scenario list: CPs, conditions (existing/proposed), return periods.
- Run log for the project (`00_Admin/run_log`) with the D17 terms-approval line.
- For QC: reported peaks (from the export itself) and, for rebuilds, the old report's peaks.
- Saved NOAA Atlas 14 upper 90% depth arrays per CP (comparison array, D21).

## Operating rules
- **Confirm the source document and the table/appendix** holding the basin parameters before
  extracting. Parsing is heuristic: show the parsed values and have the user confirm before running.
- **Terms of use (D17):** JCO approval is recorded once per project in the run log; after that,
  interactive and batch runs click I Agree without asking again. If the line is missing, ask JCO
  once and write it (default, to confirm).
- **Run mode (D18):** interactive (browser automation tool on a visible browser) for a few CPs;
  batch (Playwright, Edge channel, headless or isolated window) for more than a few. Both are
  supported; the batch is the standard for 10+ CPs.
- **Native inputs:** use the native runoff parameters for the selected cover and soil group; no fixed
  CN (e.g. CN 86) carried in. Vegetation on graded ground = program default, 20% per NORTHLOOP-013,
  verified against the 7.4 auto-fill before each batch; the old 5% Desert Brush rule is removed
  (D20, default, to confirm). Valid watershed types include Mixed / Undeveloped-Valley.
- **Tc** = the program value, 5 min minimum. Never call time to peak "Tc".
- **Rainfall (D21):** the in-app Fetch Rainfall governs; script-written depths are only the
  comparison array; record the Atlas 14 edition served.
- **Preparer:** userName = `Psomas (<initials>)` before Calculate.
- **Peaks and series (D19):** the native export is kept unchanged as the record; a separate
  peak-adjusted copy is used for routing with the added volume logged; the QC workbook reports both
  the sampled max and the program-reported peak. Report tables use the program-reported peak.
  New reports: native output is the reference (0.0 cfs tolerance). Rebuilds: the old report is the
  target.
- **DSS output is v7 only** (the only version writable from the container). INST-VAL, CFS, 1Minute.
- One PC-Hydro version per analysis, stated the same in criteria, methods, results and the software
  register.
- Deliver downloadable files for everything (CSV, XLSX, PDF, .pk6, DSS) and list them.

## Steps

### Phase 1: Extract basin inputs from a report
1. `python3 scripts/extract_basin_inputs.py --in <report.pdf|.xlsx|.docx> --out-stem <stem>`
   (EKOS: GIS venv python by full path). Produces `<stem>_basin_inputs.csv` (area, CN, C, Tc, lag,
   % impervious, reported Q by return period) and `<stem>_report_text.txt` for manual review.
2. Refine by hand where the report layout defeats the regex. Show the table; get the user's
   confirmation before any run.

### Phase 1b: GIS build of CPs and .pk6 files (large sites, offsite inflows)
1. Gather the structure inventory: master plan inventory and DOT as-builts (size, station, invert)
   for each cross-culvert or entry point.
2. Condition the DEM (10 ft or finer per D54 hydrology grid; WhiteboxTools least-cost breach, D8
   pointer and accumulation, streams >= 5 ac, slope). Close rasterio datasets explicitly.
3. Place CPs by rule: IN (offsite inflow >= 5 ac), OUTR/OUTX (exits across an exclusion or other
   boundary), junctions, and one CP per cross-culvert.
4. Build incremental and total watersheds, longest watercourses, segment slopes, land-use and soil
   overlays. Run the nested-area check (drainage-report-build) before any flows are summed.
5. Write one PC-Hydro 7.4 `.pk6` (JSON) per CP under 1 sq mi. Atlas 14 upper 90% depths at the
   centroid may be written as the comparison array (D21). Do not hard-code vegetation density.
   CPs over 1 sq mi go to hechms-headless.
6. Where the watershed to a culvert cannot be defined, use culvert capacity as the upper bound of
   inflow and say so in the inflow register.
7. Keep a tracked rerun list for CPs whose inputs change after a DEM extension.

### Phase 2: Run PC-Hydro (choose mode)
- **Interactive (few CPs):** follow `reference/pchydro_web_workflow.md`.
- **Batch (more than a few CPs):** follow `reference/pchydro_batch_automation.md` (probe, vegetation
  auto-fill check, per-CP loop, failed-CP rerun).
Both modes, per CP:
1. Load the `.pk6` via File > Open (initialize the dialog before setting the file input); wait for
   the CP field to populate. Name the CP field with the basin id.
2. Set userName; read back every native input and compare to the source; quantize flow-length
   segments to whole ft summing to the native total and soil shares to whole percent by largest
   remainder; log each precision change; stop the CP on any other mismatch.
3. Coordinates at 4 decimals; in-app Fetch Rainfall; wait for Matches and the 100-yr 1-hr value;
   compare at 2 decimals; record the edition.
4. Calculate; wait until calcDate changes and qp100 is filled; read q100 and tc100.
5. Save the program PDF (check content-type is application/pdf), the 1-min hydrograph CSV and the
   recomputed `.pk6`; write hashes and a peaks table.
6. Log failed CPs and rerun only those.

### Phase 3: Offsite and model inflows (when hydrographs feed a model)
1. Enter each flow as an inflow BC at the culvert outlet or domain edge.
2. Add every inflow to the model inflow register with its source (study, new PC-Hydro run, or
   capacity bound).
3. Run with the PC-Hydro version the reviewing agency accepts.

### Phase 4: Export QC and audited routing copy (D19, HJR-C03)
1. Run:
   `python3 scripts/hydrographs_to_xlsx.py --out <CPs>_hydrographs.xlsx --adjusted-csv <CPs>_routing.csv --native-csv <CPs>_native.csv [--targets old_report_peaks.csv] <CP-*.csv>`
   - Reads native exports (reported peak from the `Peak Discharge:` line) or plain tables plus
     `--peaks` (series, reported_peak_cfs [, equation_volume_acft]).
   - Sheets: `Peaks` (sampled max and time, reported peak, difference, report table value, native and
     adjusted integrated volume, peak-adjust and tail-close added volume, equation volume, target
     comparison), `Adjustment_Log`, `Native` (unchanged), `Peak_Adjusted` (series `_ADJ`).
   - Exit code 2 when any flag is raised (step not 60 s, no reported peak, reported below sampled,
     target mismatch). Resolve or explain each flag before Phase 5.
2. Confirm the actual sample spacing is 60 s (the script checks the file, not the UI setting).
3. Expect the sampled max to differ from the reported peak; the adjusted copy replaces the maximum
   ordinate with the reported peak. A reported peak below the sampled max is not adjusted; it is
   flagged for review against the printout.
4. Report equation runoff volume, integrated hydrograph volume and adjustment volume separately. Do
   not reject an export because they differ; there is no volume-equality gate.
5. Nonzero tails are closed with one extra minute to 0 cfs in the adjusted copy; the added volume is
   logged.
6. Peak QC: new reports compare the report table to the reported peak at 0.0 cfs; rebuilds compare to
   the old report's peaks (`--targets`, `--target-tol` if JCO sets one). Resolve discrepancies before
   building DSS.
7. Offer an overlay plot of native vs adjusted hydrographs for QC (kept in 40_QC, D30).

### Phase 5: Build DSS for RAS and HMS
1. Use the routing CSV from Phase 4 (first column `Time_min`, one cfs column per series, `_ADJ`
   names). If the script wrote `_gridN` files, the series are on different time grids: re-export at
   1 min rather than mixing grids.
2. `python3 scripts/build_dss.py --csv <CPs>_routing.csv --out-stem <stem> --variant both --apart <PROJCODE>`
   writes `<stem>_RAS.dss` (A-part blank) and `<stem>_HMS.dss` (A-part = project code).
3. Reopen each DSS and verify every ordinate, interval, units, type and volume against the routing CSV
   (`reference/dss_formats.md`, round-trip check).
4. Check whether the RAS model reads DSS or inline hydrographs before choosing the BC method
   (`reference/dss_formats.md`).

### Phase 6: Deliver
1. Deliver: native exports, program PDFs, `.pk6` files, QC workbook, routing CSV, both DSS files,
   hashes, run log.
2. Note that HEC-HMS gages and HEC-RAS DSS BCs must be **repointed and the pathname re-selected**,
   and that models must be **recomputed** (model-run-supervisor rerun gate).
3. Report appendix: native printouts and native hydrograph exports (D38). The adjusted copy and its
   added-volume log go in the hydrology QC note, not in place of the native output.

## Gotchas
- App JS is obfuscated; button/field names and page functions (openProject, fillSCS, hydroCalc,
  hydroGraph, printFile) had to be found with probe scripts before automation worked
  (RKN-004, SAH-007).
- Vegetation density auto-fill behaviour had to be probed from the live page; confirm default cover
  densities match the PC-Hydro guide before a batch (SAH-007).
- File-chooser events timed out until the File-Open dialog was initialized properly
  (EKOS-LOCAL-006).
- Soils 52.263/41.418/6.318% rounded to 52/41/6 (total 99) failed validation; largest remainder
  52/42/6 passed (EKOS-LOCAL-006).
- Full-precision GIS lengths failed the native length-sum check (EKOS-LOCAL-006).
- Never set fake valid flags or force Calculate enabled (EKOS-LOCAL-006).
- Direct HTTP rainfall request returned 403; use the in-app fetch (EKOS-LOCAL-006).
- The PC-Hydro guide cites an older Atlas 14 edition than the data now served; record the edition
  fetched (EKOS-LOCAL-006).
- pdf.php sometimes returns text/html instead of a PDF (seen at CP-103); check content-type and retry
  the CP (RKN-004).
- A local CORS helper server (127.0.0.1 with private-network headers) was used first to feed records
  to a tab; the Playwright file-input route is simpler (RKN-004, SAH-007).
- 67 subbasins ran in about 25 min once the batch worked (SAH-007).
- Web app changes can break the batch; keep the .pk6 inputs so runs can be repeated by hand (SAH-007).
- 9 failed PC-Hydro tasks on one project before the adapter was stable (NOAA mapping x3, basin
  import x4, road scenario x1, benchmark) (EKOS-LOCAL-006).
- Window move/resize re-renders the page and resets state (pchydro-hydrographs v1).
- Match the in-file Concentration Point field to the basin id; scripts key off it, not the filename
  (pchydro-hydrographs v1).
- Owner correction: at steps other than 1 min the peak never matches and has to be adjusted by hand;
  export at 1 min and use the audited adjustment (EKOS-LOCAL-007).
- An invented 1% volume-equality gate wrongly flagged an export as corrupt; the county manual defines
  the hydrograph integral as an approximation (EKOS-LOCAL-007).
- The export QC applied across 4 catchment scenario sets on one project (benchmark, basin, road
  crossing, HMS inflows) (EKOS-LOCAL-007).
- data_type not INST-VAL makes HMS read all zeros (pchydro-hydrographs v1 dss_formats).
- Saved standards still carried the old 5% Desert Brush graded-ground rule; JCO's correction
  overrides it; purge it wherever found (NORTHLOOP-013).
- rasterio prints "NoneType has no attribute exc_info" tracebacks at interpreter exit; harmless;
  close datasets explicitly to keep logs clean (RKN-003).
- CPs whose inputs changed after a DEM extension need a tracked rerun list so carried results stay
  consistent (RKN-003).
- The source report covered only the central reach; north and south reaches had no culvert
  inventory and had to be scoped as new work (ELTORO-009).
- A reviewer had already questioned the PC-Hydro version used in the source report; confirm the
  version with the agency first (ELTORO-009).

## QC checks
Pull: `get_qc_rules('hydrology')`, plus `get_qc_rules('pima-rfcd')` / `('marana')` / `('tucson')` /
`('sahuarita')` by jurisdiction, and `get_qc_rules('model-runs')` when hydrographs feed a model.
This skill must pass before hand-off:
- Terms-approval line present in the run log (D17).
- Native input read-back matches scenario values field by field before Calculate; every precision
  change logged.
- No manually typed vegetation density or fixed CN on graded ground unless JCO approved it (D20).
- Fetched rainfall matches the saved Atlas 14 upper 90% arrays at 2 decimals; edition recorded (D21).
- Printout PDF content-type is application/pdf; userName shows `Psomas (<initials>)`.
- Export step is 60 s in the file; units cfs.
- Peaks sheet shows sampled max and reported peak for every series; report tables use the reported
  peak; new reports match native at 0.0 cfs; rebuilds compared to the old report (D19).
- Adjusted copy is separate from the native export; added volumes logged; no volume-equality gate.
- DSS round trip verified ordinate by ordinate; INST-VAL, CFS, 1Minute.
- Every inflow BC appears in the inflow register with its source.
- One PC-Hydro version stated throughout the report and software register.
