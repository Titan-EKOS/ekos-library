trigger: Result rasters were generated from plan HDFs by a script (hecras_result_rasters.py
  or similar) instead of RAS Mapper stored maps.
steps:
- Confirm which tool made each delivered raster (script tag in name, README, or matching
  script in the folder).
- Compare depth, WSE and velocity at 5-10 points against a RAS Mapper max map of the
  same plan and terrain.
- Check the terrain the script used for depth; it resolves the geometry terrain name
  to a .vrt or .tif by basename only.
- State in the deliverable that velocity is a max face velocity proxy and screen single-cell
  spikes before quoting peak velocity.
gotchas:
- The script burns one max WSE per cell polygon (flat per cell), not the sloped RAS
  Mapper surface, so depth shows steps at cell edges and differences can be noisy
  at wet-dry edges.
- Velocity is the max of face velocities around each cell and runs higher than RAS
  Mapper cell velocity.
- Depth uses the base .vrt; terrain modifications stored only in a terrain HDF are
  not seen. Here mitigations were in geometry so all plans used one terrain, but this
  must be checked each time.
- Output was regenerated at 10 ft cells from 0.6 ft terrain; spot values are sampled
  from the coarse grid, not source values.
- The script and its .skill package were shipped inside the delivered model folder;
  check deliverables for internal tools before release.
