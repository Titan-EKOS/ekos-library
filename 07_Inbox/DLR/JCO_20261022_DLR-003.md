title: Handle a large received terrain package and broken stored maps
type: skill
function: hydraulics-model-run
trigger: A received RAS model includes multi-GB terrain rasters, several scenario
  terrains and stored RAS Mapper maps.
steps:
- Budget disk at about 2-3 times the zip size (zip plus extracted copy plus new maps);
  this set was an 85 GB zip and 170 GB on disk.
- List Terrain folder sizes and read each scenario .vrt to see which source tif it
  points to and at what cell size.
- Note that scenario terrains that point to the same base tif carry their modifications
  in the terrain HDF or geometry, not in the tif; do not compare scenarios from the
  tifs alone.
- Identify duplicate source tiles (same tile in two folders) and do not copy them
  again to other drives.
- Check each stored map in the .rasmap for its Terrain name and StoredFilename; if
  the terrain name or output folder is not in the delivered set, regenerate the map
  in RAS Mapper.
- Never open the multi-GB tif or HDF in a viewer to inspect it; use the .vrt and .rasmap
  text.
gotchas:
- Base terrain was one 53 GB tif at 0.615 ft cells (about 430,000 px square) plus
  a 2.2 GB terrain HDF; the three scenario terrains were VRTs over that same tif.
- Stored depth maps referenced terrain clone names that were not delivered and output
  folders that did not exist, so they would not display until recomputed.
- The same USGS and county DEM tiles were delivered twice in two Terrain subfolders,
  including two 6.8 GB county DEM copies.
