title: Intake check of a received HEC-RAS 2D model set (plan, geometry, flow pairing)
type: skill
function: hydraulics-model-run
trigger: A HEC-RAS 2D model set is received from another firm or agency and must be
  reviewed, rerun or mapped.
steps:
- Unzip to a working copy and keep the delivered zip untouched as the record copy.
- Read the .prj as text and list registered Geom, Unsteady and Plan files.
- For each .p## read Plan Title, Short Identifier, Geom File, Flow File, Program Version
  and Computation Interval; build a plan-geometry-flow table.
- Compare the table with every .p##, .g##, .u## and .hdf on disk; flag files on disk
  that the .prj does not register and .prj entries with no file.
- Flag stray copies (renamed .hdf, .tmp.hdf, .snapshot.hdf, Backup.p##) and do not
  treat them as results.
- Match the table to the report or data dictionary scenario tokens (existing, future,
  each mitigation) before trusting any result raster.
- Note RAS versions used (flow file, geometry, plan) and open in the same or a newer
  version on a copy only, since opening rewrites plan and geometry files.
gotchas:
- Plan p01 (floodwall, existing event) existed on disk with a 1.5 GB result HDF and
  was cited in the delivered data dictionary, but was not registered in the .prj,
  so it did not appear in the RAS plan list. Fix - add the plan back through the .prj
  or open the .p01 directly.
- A stray renamed copy of a plan result HDF (p02 with extra letters appended) was
  the same size as the real one; easy to map the wrong file.
- RAS Mapper listed a 91 percent snapshot HDF as a results layer next to the completed
  run; check the layer name for Snapshot before mapping.
- One geometry HDF appeared twice in RAS Mapper under two different names, and a stub
  geometry HDF (0 MB) was referenced but not in the .prj.
- Plans mixed 30 s and 1 s computation intervals and RAS 6.70 / 7.00 / 7.01 files;
  a test plan created after receipt changed the project Current Plan. Record the as-received
  Current Plan before editing.
