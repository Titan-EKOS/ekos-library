type: skill
function: data-gathering
trigger: Proposal or Phase 1 start for a site with several adjacent developments,
  roads, plants or master plans that share the same wash or floodplain
steps:
- Make one subfolder per adjacent project under an Adjacent Studies and Plans folder
  (state land master plans, school drainage report and as-builts, road extension,
  treatment plant, recorded subdivision plats)
- For each item log type (drainage report, CMDP, floodplain memo, as-builts, shapefiles,
  ERR, OHWM memo), date, author agency, and what it controls at the site boundary
  (peak Q, floodplain limit, culvert size, berm)
- Check for supersession memos before using any older study (example - 2018 LMW-East
  TDN supersedes 2009 Basin Management Study delineations inside its study limit)
- Pull GIS layers (100-yr floodplain, PAD boundaries) into the project coordinate
  system and note their date
- Record which adjacent item fixes a boundary condition for the zoo site (inflow Q,
  tailwater, berm crest, culvert invert) in a one-page summary table
- Note planned facilities that may change drainage later (future WWTP outfall to the
  wash, zoo wetlands, road used as berm)
gotchas:
- The same school as-built set was filed three times (two folders plus a Copy file);
  dedupe by hash before reading so it is not reviewed twice
- Large consultant shapefile sets (120-280 MB) were copied into two places under State
  Land; keep one copy and link to it
- Scratch output (_tmp_render PNGs of plan sheets, a .write_test file in Submitted)
  was left in the synced project folder; keep render scratch outside the project share
- Non-drainage items (pavement, traffic, cultural, roundabout) sit in the same Reference
  folder; tag them so the drainage review skips them
